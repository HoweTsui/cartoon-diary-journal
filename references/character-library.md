# 人物图库与关系

## 当前 0.2.4 角色几何覆盖

所有新角色和旧角色重绘的首轮肢体杆部统一采用头宽约 `1/32` 的超细目标；旧版 `1/28` 仅作兼容上限，`1/24` 为绝对失败上限。头部、手部和脚部保持确认版尺寸，躯干和头部以下身体段按上一版卡片约 90% 处理，身体比例缩短约 10%。每名角色继续只用 25°–35° 偏正半侧面，禁止正面、真正 90° 正侧面和单眼全侧面。以下旧版锚点文字如出现 `1/28`，只按兼容上限解释。

头脸是独立的最高优先级身份锚点：复用确认版近圆头宽/头高、两枚同直径圆眼、短横向开放人鼻、低位分离嘴和短弧后的空白断口；不能因照片、场景动作、表情或发型把头拉长、眼睛放大、鼻子下垂或把鼻嘴合并。

## 数据地位

`assets/character-library/character-graph.html` 与 `character-lineup.png` 只提供本地结构和画风参考。公开可复现的构建默认模板是 `assets/style-reference/character-graph-demo.html`；仓库内任何人物名称、头像和关系都不能作为新任务的默认人物库，每次实际任务都必须整体替换为本次数据。

每个实际任务必须生成一份任务专用图谱和人物图集。图谱只表达全局身份与关系，不写日期、周几、当日事件或时间线。人物图集保留为完整角色总览；图谱头像优先使用每个角色独立的 1:1 方图，避免从整张拼图裁切时丢失上半身或偏移。

## 生图前匹配

按以下顺序检查日记里的每个角色：

1. 在任务 HTML 的 `graph-data.nodes` 中匹配角色 ID 或准确姓名。
2. 未精确命中时，再用身份说明、外观锚点和人物备注做唯一匹配。
3. 唯一命中时，读取该节点的 `col`、`row` 和 `anchors`，从任务人物图集中使用对应格位；若有 `avatarSrc`，同时加载该角色独立的 1:1 头像。
4. 无命中或多重命中时停止生图，列出角色并要求用户提供清晰图片。不得猜测或套用模板人物。
5. 收到图片后先按现有图集风格转绘，再把新角色写入任务图集和图谱，重新构建 HTML 并再次执行匹配，全部通过后才继续日记生成。

## 实际数据结构

以 `assets/templates/character-graph-data.example.json` 为结构模板。每个节点必须包含：

- 唯一 `id` 与本次任务的实际 `name`。
- 实际 `role`。
- 与任务人物图集一致的 `col`、`row`。
- 可选 `avatarSrc`：相对 HTML 的独立 1:1 角色头像路径，例如 `avatars/ahao.png` 或 `avatars/ahao.svg`。一旦任一节点使用该字段，所有节点都必须各自提供唯一路径；每张图均需按同一套半侧面、双正圆豆豆眼、人兽分鼻、极细四肢、可见配饰（包括眼镜框/镜桥/镜腿）与统一线重生成。
- 可选 `avatarFocusX`、`avatarFocusY`（0–1）：头像裁剪焦点；人物默认约为 `0.5, 0.36`，动物可把 `avatarFocusY` 调低或调高以完整容纳全身。
- 图谱初始位置 `x`、`y`。
- 至少四条可观察 `anchors`，并必须覆盖：25°-35° 偏正半侧面朝向与确认版图集固定 canonical 直径的双正圆豆豆眼（外侧眼留白）、脸型及前外侧短弧后到鼻根的空白断口、人类清晰可见的开放线描鼻或动物清晰可见的实心黑鼻、低位嘴、无内耳修饰线的发型/耳尾或配饰（眼镜框、镜桥和镜腿若出现，线宽与主体同为 5–6px 纯黑线）、窄身板与统一目标粗细的极细四肢（人物上臂/前臂/大腿/小腿以及动物不含爪掌的前后肢首轮目标约头宽 1/32、绝不超过约 1/24，彼此粗细误差不超过 10%）、服装/黑块及鞋或爪掌。长鼻方向仅在该人物本身具有长鼻时记录。
- 可选的长期 `notes`；不得放某一天的日志事件。

每条关系必须包含实际 `source`、`target`、`label`、`type` 和 `curve`。关系端点必须存在于同一份节点数据中，两个人物之间只保留一条边。

## 整体替换占位数据

不要在模板数组后追加人物或关系。运行：

```bash
python3 scripts/build_character_graph.py <actual-character-data.json> \
  --output <task-output>/character-graph.html
```

脚本整体替换 HTML 的 `graph-data`，输出标记为 `status: actual`，并校验所有关系端点、图集格位、独立头像路径和旧版头像裁切信息。把实际人物图集按 `atlas.src` 指定的文件名放在输出 HTML 同目录；若使用 `avatarSrc`，再把 `avatars/` 等目录按相对路径复制到 HTML 旁。数据变化后缓存键自动变化，不会加载上一个任务的本地人物。

交付前检查：

1. `graph-data` 与实际 JSON 的人物数、人物字段、关系数和关系字段完全一致。
2. HTML 中没有任何未属于本次任务的旧占位姓名、身份、锚点、备注或关系描述。
3. 人物图集的格位数、人物顺序与 `col`、`row` 完全一致；独立头像文件均存在、为 1:1，并与节点 ID 一一对应。日记本模式要求所有节点都有唯一 `avatarSrc`，不接受图集裁切回退。
4. 打开 HTML 检查每个节点和右侧人物卡：独立头像优先显示、上半身完整、水平/垂直居中；缺失独立头像时才显示图集裁切，并把该节点列入迁移清单。
5. 图谱页面没有日期、周几或日记时间线。

## 图集更新

对缺失角色使用用户图片时，只把原图作为当次临时身份输入。先提取发型轮廓、服装/配饰块面、体态、宠物耳尾与毛色，再以当前人物图集作为唯一转绘标准：复用中粗黑线、25°-35° 偏正半侧面、双完整正圆豆豆眼（直径与确认版图集 canonical diameter 相同且不得放大，外侧眼留白）、前外侧短弧后到鼻根的空白断口、人兽分离的单鼻语法、清晰可见且不被遮挡的人类鼻、低位嘴、耳内留白无修饰线、窄身板、人物上臂/前臂/大腿/小腿首轮目标约头宽 1/32（绝不超过约 1/24）的极细双线管状四肢、偏大扁鞋/略大爪掌和统一头身比。人物使用上方断开的线描半椭圆鼻且绝不填黑；动物使用物种正确、清晰可见的单一实心黑鼻且绝不使用人物鼻。不得把照片的皮肤、毛发、材质、光影、正面角度、真实比例或背景带入结果，也不得强制所有角色使用长鼻。生成后对照图集检查视角、线重、五官位置、眼点直径、断口、人兽鼻型、鼻子是否存在、耳内是否空白、四肢结构和黑白块面；任一项漂移就重生成。不得嵌入或复制原图。每个角色先生成独立 1:1 方图，再按相同顺序拼成完整总览图集；不要把总览图集重新裁成不等比例头像作为最终资产。图集保持规则等分网格；超过现有容量时调整 `atlas.cols`、`atlas.rows`，同时重新生成整张任务图集，避免画风和裁切漂移。

## 图集与日记一致性门禁

- 日记中的每个角色必须逐场复用图集对应格位的头型、朝向、双眼间距、鼻型、嘴位、发型/耳尾、服装黑块和肢体比例；不能只保留相似发型。
- 每个场景在生图前必须建立逐角色卡：角色 ID、图集 `col`/`row` 和该角色全部 `anchors` 缺一不可。主角不能成为配角、路人或宠物的默认模板；每个出场角色必须独立匹配自己的卡和图集格位。
- 任一配角或宠物变成泛化卡通、复用主角的头脸/服装/肢体，或无法对应到该场角色卡，均是 P0 失败：整页重生成，不得仅修主角。
- 图集中的人物与动物也必须使用同一套半侧面规则，禁止图集为正面而海报为半侧面，或反过来。
- 同一角色在日记任一场景出现正面、黑色人鼻、人物式动物鼻、鼻子丢失/被遮挡、耳内修饰线、眼点不规则/放大、眼镜框/镜桥/镜腿线宽与主体不一致、上臂或前臂/大腿/小腿/动物不含爪掌的肢体杆部没有统一保持首轮约头宽 1/32（绝不超过约 1/24）、粗身板、粗肢体或缺少脸部断口时，身份匹配判定为失败，重新生成受影响整页。
- 角色锚点若引用更早的 `1/22` 上臂或 `1/18` 腿部描述，只视为失败上限；任务首轮必须按统一 `1/32` 极细肢体目标生成，`1/24` 只作绝对上限。

## HTML 交互

- 节点头像优先读取 `node.avatarSrc` 的独立 1:1 方图，使用中心对齐规则显示；头像文件应已将上半身放在方形安全区内，不能依赖 CSS 放大或偏移来补救构图。
- 没有 `avatarSrc` 的旧节点继续使用 `atlas` 的 `col`/`row`/`avatarFocusX`/`avatarFocusY` 裁切，保证历史图谱可打开；新任务若仍依赖该回退，只能视为未完成迁移。

- 浏览态只显示人物和关系纯文本，不显示编辑输入框、删除按钮、新增人物或新增关系表单。
- 点击“编辑”后显示人物字段、新增人物和新增关系表单。
- 编辑态双击画布上的连线名称，使用内联输入框修改；按 Enter 保存并持久化，按 Escape 取消且不改原值。
- 编辑态从节点右侧 `+` 控制点拖到另一节点可吸附建连。
- 编辑态把已有连线端点向节点外拖出可断开关系。
- 拖动任一人物靠近其他人物时，其他节点平滑避让；碰撞范围必须包含人物姓名，最终节点和姓名均不得互相遮挡。
- 点击“编排”时，无环图使用层次布局，有环或稠密图使用力导向布局；完成后可用撤销、重做恢复任意位置快照。超过 50 个节点时必须分帧计算。
- 节点位置和编辑结果写入按人物数据隔离的 `localStorage`；要正式入库仍需重新运行构建脚本并同步任务人物图集。
- 从日记本打开图谱时，必须支持 `character-graph.html?character=<角色ID>`：页面自动选中并居中该节点。书内只放只读关系概览和跳转链接，不能嵌入图谱 Canvas、拖拽或缩放交互。
