# 生成门禁

调用前运行结构预检：检查schema、protagonistId、每场角色ID、身份版本审批、图片职责及文件、原文存在、显式1–5选景、文字预算和几何可行性。每天只允许一张3:4海报；5场景必须在同一张图内保持从上到下的阅读顺序。新角色不需要预先拥有角色图谱；先做onboarding预览和草稿人物档案。草稿可在用户要求的测试中复用，不能当正式批准版。

生图时附上所有声明的图片；身份源图只提供大特征，style/layout不提供角色身份。读取style-system.md并使用geometry.json生成的目标，不能继承旧图错误比例。

多表情图须逐格检查，不能用其中一格代表整张：每段裸露肢体只有两条外轮廓、内部纯白；每只猫与狗都保留与嘴分离的黑鼻。任一格多中线或漏鼻都不能标为通过，应局部修复并重查整张。

出图后人工逐角色核对：身份锚点、物种、人类偏正半侧面与宽扁开放C形鼻；鼻根上方另有明显净白断口，不能与前脸线几乎相连。左右点眼均正圆等径，不因透视变椭圆，半睁眼珠仍按圆形遮挡；闭眼弧保持。正常及轻中度无眉；嘴在低位偏耳侧与鼻斜向分离，长度和形状匹配具体表情，不能统一短钩；细脖子、等粗描边、全部开放线端圆头。再核对手脚完整、段长、白缝与等粗肢体。动物另查短细四肢、大爪、光滑无毛轮廓，不能用人类脸型角度代替物种检查。逐场核对动作、数量、关键道具、关系和短文本；检查纸张边界、居中日期标题、右侧备注与完整留白。结构测试通过不等于图像通过。

孤立手臂、小腿、眼镜或单处文字缺陷可以使用图像局部编辑，明确保留其余身份、构图、动作和文字；修复后重新完整视觉验收，不能只看修改区域。系统性身份或结构漂移、缺陷无法安全隔离时重生整页。最多两轮修复后记录未解决问题，再决定后续；预览必须明确为草稿，用户批准当前版本前不得替换正式角色或海报。
