# 七步执行记录与双端交付

保留 SKILL.md 原七步，不增加新的日常审批层。开始时确定用户实际使用的笔记工具、当天文档位置、同一本 3D 日记本及其数据清单位置；已有配置直接复用。没有目标或权限时可先产出草稿，但不能声称已入库。

## 各步只留必要证据

| 原步骤 | run.json 的 id | 保存什么 |
| --- | --- | --- |
| 读取参考 | references | 本次采用的规则/母版版本与哈希记录 |
| 照片归档 | photos | 归档清单；没照片可注明 not-needed 和原因 |
| 角色 | identity | 特征对应表、人物卡与真实批准记录，或已有批准版本 |
| 选景/请求 | scenes | brief、逐场 request 和实际调用记录，或已确认动作复用记录 |
| 海报 | poster | 完整 PNG、合成配置、颜色检查及实际看图结论 |
| 图谱/日记本 | graph-book | 更新后图谱、书籍数据清单、v3 data/manifest.json |
| 笔记正文 | note | 实际日期文档/平台页面、图片附件、读取回来的内容及预览 |

实际使用已有卡/动作也记录其文件和来源，不需要重复生成。记录保存到私人任务目录，不记录令牌、账号秘密，不在发布包中加入真实用户资料。文件证据包含 path 和 sha256，记录发生时保存，不事后编造工具调用或用户批准。记录顺序用于查漏，不能声称它自动监控了 Agent 全部行为。

## 笔记工具适配

- Obsidian/本地 Markdown：在用户指定 vault 或日记目录构建日期文档和持久附件，再在实际笔记工具查看；不要把 task-output 示例当成已经写入用户 vault。
- Notion、飞书或其他文档平台：使用该环境已有连接器/CLI，先上传成品及照片附件，再插入原生正文与图片块。复用当天页面，写入后读取回来并实际预览。保存页面 ID/URL、图片块/附件 ID 和脱敏调用结果，不贴临时本机路径。没有对应工具或权限则清楚列为待同步。
- 本地 HTML 是可审查预览，不等于任何云端笔记软件已同步；用户明确选本地文件作为目标时才按本地交付处理。

## 3D 日记本同步

将同一份最终高清 PNG 加入用户现有书籍清单，保留原 book.id、其他日期与角色资料。同日条目按确认版本更新，不新增同日重复条目。沿用旧构建器数据契约，再用 build_diary_reader.py 导出 v3 新目录；核对新 data/manifest.json 中日期、条目及海报文件后，向用户交付新的预览入口。不要只改旧清单而仍打开过期 v3 目录。

笔记中的压缩 PNG 与高清海报应画面一致，书籍中 PNG 应与最终高清版字节一致。用同一海报来源实现两端一致；不在笔记工具或日记本里重新绘制另一张海报。

## 运行后核对

从 `assets/templates/diary-run.example.json` 建立任务 run.json。证据路径相对 run.json（本地个人目标也可用绝对路径）。交付前运行：

```bash
python3 scripts/verify_diary_delivery.py task-output/my-diary/run.json
```

检查器验证七步记录及证据哈希、本地日期文档是否真实嵌图、压缩照片数量/顺序、海报格式、v3 同日条目是否唯一以及是否使用同一张海报。缺少任一预览证据或内容核对记录则 pending；缺失文件、不同日期、旧海报、普通下载链接、漏图则 blocked。

`evidence-complete` 只表示所记录的证据与文件一致，不等于自动审美评分或独立证明助手严格执行。实际调用附件、照片与身份相符、文案原意及画风仍需查看。远端笔记即使有本地回读记录也始终提示需要实时连接器核验；不能用复制的截图或自填状态绕过远端写入。

最终答复分别给出：正文位置与是否实际入库、3D 日记本入口与日期、完整海报、尚未完成的同步项。两端都完成才说“日记已归档并同步日记本”。
