# QA Checklist

## 必过项

- 生图前已读取本次任务的 `character-graph.html`：每个出场角色均按 ID/准确姓名/唯一身份锚点命中，使用了对应图集格位；缺失或歧义角色已停止生图并完成补图入库，未用旧占位角色顶替。场景只使用图谱中已登记的关系。
- 是严格 9:16 长竖版，场景沿页面由上至下连续展开，没有分格边框。
- 页面最顶部清楚显示 `YYYY.MM.DD 周X`，日期与真实周几一致。
- 日期下方有一句标题。
- 人物与物件只有纯黑和纸白；纸面只有 14-18 条等距的极浅青蓝横线。
- 人物使用身份图集的略圆但不几何化头型、两个略拉开距离且尺寸/视觉粗细一致的黑点眼、侧后小耳、鼻下偏低的小嘴；不画眉毛。前外侧眼旁从发际高度到鼻根的头部轮廓必须保持长断口，不得被任何线补齐；额头、鼻根、脸颊和下巴的可见外轮廓必须连续平滑，不得出现折点、阶梯、硬直角或突然转折。每人只有一个鼻子，鼻型、鼻尖方向和表情匹配身份图集。鼻子本体应为略扁的小椭圆半椭圆，断口位于上方，端点应停在双眼下方并只产生轻微遮挡；不得画正圆、完整闭合 O、长鼻梁、眉线或额头线；长鼻只用于身份锚点明确要求的人物。人脸双眼、单鼻、嘴不得缺失；动物必须保留物种需要的双耳、双眼、口鼻、四肢与尾巴，并使用符合物种的单一实心黑色动物鼻：狗在口鼻前端，猫更小且位于两眼下方中央；动物眼睛为无白色高光/反光的实心黑点；不得出现人物 C 形鼻、鼻梁线或鼻孔。使用约 5–6px（1024px 宽画布）的统一黑线、极细双线管状手臂与前臂、略放大但仍小巧的掌部和 3–4 个短指弧、细长双线小腿和偏大扁鞋；手臂实体宽度约为头宽的十分之一，掌宽不得超过前臂的 1.3 倍。
- 纯黑块只用于嘴、头发、上衣或鞋；线条稚拙但清晰，不是圆润厚描边。
- 没有纸纤维、颗粒、噪点、斑点或复古做旧。
- 没有写实光影、体积、皮肤或食物渲染。
- 每个固定人物匹配图集的头型、双眼位置与间距、鼻型与鼻向、鼻子自身开口、眼嘴、发丝、配饰、黑块位置、服装结构、双线腿和鞋形。
- 本次新增人物若来自用户上传图片，照片只贡献身份线索；其线重、五官简化方式、鼻子自身开口、四肢结构、头身比和黑白块面必须与现有人物图集逐项一致，不能出现半写实或另一套卡通风格。
- 宠物必须是平面简化剪影；只保留头、躯干、口鼻、耳、四肢/脚掌和尾巴等大结构，不使用彩色毛色块；长毛品种最多 3–5 个大圆钝轮廓起伏。不得出现真实毛发束、逐撮毛刺、密集围脖、胡须细节、任何白色眼睛高光/反光点、毛色渐变或写实肌肉结构。
- 动物的躯干、前后肢、脚掌、尾巴和物种正确的单一黑色动物鼻应保持简洁，并与该动物的身份锚点一致；不得把某只动物的比例、口鼻或坐姿套给另一物种。狗头须明显大于躯干、双黑点眼距偏宽、鼻子为口鼻前端的单一黑椭圆，脚掌为短粗圆弧并且每脚仅 1–3 个简化趾口；不得出现写实犬类解剖、精细脚趾或关节。猫鼻不得变成狗鼻大小或落在口鼻尖端。不得出现人物鼻子、鼻梁/鼻孔、写实四肢或三角湿鼻。
- 表情变化只改变眼睛开合/圆睁/同向斜视、嘴洞/嘴角/简化露齿和不超过两个外置情绪符号；中性脸不画眉毛，愤怒或疑惑仅允许 1–2 条临时短情绪线。头型、鼻子位置、发型/耳朵、手指、四肢长度、鞋/脚掌和头身比必须与中性图一致，双眼、单鼻、嘴不得缺失。
- 每个开放场景只表达一个动作；总场景数为 3-6；对话气泡不超过 4 个、每个不超过 8 个字。
- 中文短、少、基本可读。
- 没有复制私人信息或已出版作品的具体元素。

## 失败即重生成

- 日期缺失、在中部、格式错误或周几错误。
- 人物变成单眼侧脸、粗手臂、块状掌、粗壮腿、发丝腿、常规可爱儿童插画、漫画美型脸或写实人物；或所有人物被套成同一种长鼻、正圆鼻、完整闭合鼻、方盒鼻、硬直角头、脸部外轮廓折点/阶梯/突然转折，鼻子断口落在下方、鼻向与面向冲突，或五官、宠物耳朵缺失。
- 新上传人物与图集在线重、五官语法、四肢粗细、头身比或黑白块面上出现明显漂移。
- 表情导致五官缺失、常驻眉毛、身份轮廓改变，或宠物出现人物鼻子、鼻梁/鼻孔、写实鼻口、逐撮毛刺或真实毛发。
- 肢体恢复正常粗细、鞋变小，或头身比不再故意笨拙。
- 同一人物在不同格换头型、眼镜、发夹、衣服或宠物耳形。
- 出现渐变、柔光、厚重阴影、灰阶体积或彩色厚涂。
- 背景细节超过主体，或页面出现漫画分格、像 PPT、照片拼贴。
- 参考图中的姓名、日期、地点、品牌、商品或脸被复用。

## 单点修复

- 太普通：锁住图集头型、双点眼间距、单鼻结构与鼻向；改成中粗线、细长双线小腿，放大鞋，减少发丝，并加入符合其表情的纯黑嘴洞或衣鞋块面；不得为求风格而统一拉长鼻子，圆鼻必须在自身轮廓留开口。
- 太精致：删除灰阶和阴影，改成纯黑细墨线。
- 太脏：要求 smooth clean paper、zero grain、zero speckles。
- 人物漂移：重新附身份图集并逐人重复锚点。
- 文字错一处：局部编辑；错三处以上：减少文字并重生成。
- 日期错：只编辑顶部日期，不改画面。

## HTML 图谱

- 页面标题只写“人物关系图”，没有日期、周几或时间线信息。
- `graph-data.status` 是 `actual`，人物与关系逐字段等于本次任务数据；没有遗留占位人物或旧关系描述。
- 实际人物头像全部裁切到数据指定的正确格位。
- 浏览态只显示纯文本；没有人物输入框、关系选择框、删除按钮或新增人物按钮。
- 默认和选中人物状态的右侧按钮均显示“编辑”；点击“编辑”后才显示人物字段、新增人物和新增关系表单。
- 编辑态双击连线名称会显示内联输入框；Enter 保存新名称，Escape 保留原名称。
- 拖拽节点时连线实时跟随。
- 把人物节点拖近其他节点会平滑推开邻近节点；动画结束后人物圆形和姓名标签均不重叠。
- 点击“编排”会在 300-500ms 内完成位置过渡：无环图为层次布局，有环/稠密图为力导向布局；撤销、重做可恢复前后位置，手动拖拽也会进入位置历史。
- 50 个以上节点的力导向计算分帧执行，交互和绘制不应长时间阻塞。
- 从节点 `+` 控制点拖到另一节点会吸附并新增连线。
- 把已有连线端点向节点外拖出会删除该关系。
- 空白拖动画布有效；滚轮缩放以指针为中心。
- 搜索、关系筛选、复位和人物卡有效。
- 新增人物后可拖拽并显示首字占位头像；保存详情后画布和人物卡同步更新。
- 删除人物会同步删除其关系；新增和删除关系会立刻更新连线与计数。
- 刷新页面后节点位置、人物信息和关系仍保留；更换任务数据后不会加载旧任务缓存。
- 桌面与窄屏均无主要内容裁切。
